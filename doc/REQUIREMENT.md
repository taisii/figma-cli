# 研究支援ツール 要件定義書

## Part 1: 要件定義

### 1. 概要

本ドキュメントは、研究者の思考プロセスを加速させるための「**知識キュレーションツール**」の要件を定義する。

このツールは、ユーザーの視覚的なブレインストーミング（FigJam）と、手動で収集した参考文献群を統合的に解析し、外部の対話型AI（例: Gemini CLI）が消費するのに最適な、構造化された「**コンテキスト（知識ベース）**」をファイル群として自動生成することを目的とする。

### 2. 目的と背景

現代の研究プロセスでは、LLMとの対話が不可欠だが、以下の課題が存在する。

1.  **コンテキスト維持のコスト**: 対話のたびに、研究の背景やこれまでの経緯をLLMに再説明する必要がある。
2.  **非構造化情報の言語化**: FigJam上の視覚的なアイデアや、散在する文献情報を、LLMが理解できるテキスト形式に手動でまとめるのは非効率である。

本ツールは、これらの課題を解決し、ユーザーが常に文脈を完全に理解した「第二の脳」としてのAIと、即座に深い議論に入れる環境を提供することを目的とする。

### 3. 機能要件 (FR)

| ID | 要件名 | 概要 |
| :--- | :--- | :--- |
| FR-1 | **FigJamボード分析機能** | FigJamボード上のオブジェクト（付箋、テキスト、コネクター等）をAPI経由で読み込み、その構造（クラスタ、接続、タグ）を解析する。 |
| FR-2 | **手動文献の取り込み機能** | ユーザーが手動で管理する`/references/`ディレクトリ内のファイル（.pdf, .md, .txt等）を読み込み、内容を解析・要約する。 |
| FR-3 | **統合知識ベース生成機能** | FigJamと参考文献から得た情報を統合し、構造化された複数のコンテキストファイル（下記参照）を`/context/`ディレクトリに生成・更新する。 |
| FR-4 | **時系列ログ生成機能** | `run.py`実行時のFigJamボードの変更点を検出し、その変更が研究に与える意味合いを内部LLMで要約し、`RESEARCH_LOG.md`に時系列で追記する。 |
| FR-5 | **課題と仮説の抽出機能** | FigJam上の特定の記法（例: `#issue`タグ）や文脈の変化を基に、研究における「未解決の問い」と「検証すべき仮説」を`ISSUES_AND_HYPOTHESES.md`に自動でリストアップ・管理する。 |
| FR-6 | **ネクストアクション提案機能** | `ISSUES_AND_HYPOTHESES.md`の内容を基に、次に取り組むべき具体的な調査項目と、外部の高度な検索ツール（例: DeepResearch）で利用できる指示文のドラフトを`NEXT_ACTIONS.md`に生成する。 |

### 4. 非機能要件 (NFR)

| ID | 要件名 | 概要 |
| :--- | :--- | :--- |
| NFR-1 | **操作性** | ユーザーは`python run.py`コマンドの実行のみで、知識ベースの更新が完了する。 |
| NFR-2 | **相互運用性** | 生成されるコンテキストファイルは、標準的なマークダウンおよびJSON形式とし、特定のAIツールに依存しない、高い可搬性を持つ。 |
| NFR-3 | **設定可能性** | FigJam上の記法の意味（例: コネクターの色やハッシュタグが示すこと）を、ユーザーが`config.yaml`で自由に定義できる。 |
| NFR-4 | **セキュリティ** | APIキー等の機密情報は`.env`ファイルで管理する。 |

## Part 2: 基本設計

### 1. システムアーキテクチャ

本ツールは、ユーザーのローカル環境で動作するCLIアプリケーション（知識キュレーター）として機能する。対話インターフェースは提供せず、生成したコンテキストファイルを介して、外部のAI CLIとの連携を前提とする。

**データフロー:**
```
(User) --> [FigJam]
       --> [/references/*.md, *.pdf]
         |
         v
      (run.py)
         |
         v
[/context//*.md, *.json] <--> (External AI CLI) <--> (User)
```

### 2. ディレクトリ構成

```
/
├── context/             # (自動生成) 外部AIが読み込む知識ベース
│   ├── 00_README.md
│   ├── 01_RESEARCH_LOG.md
│   ├── 02_FIGJAM_SNAPSHOT.md
│   ├── 03_STRUCTURED_DATA.json
│   ├── 04_KEY_CONCEPTS.md
│   ├── 05_ISSUES_AND_HYPOTHESES.md
│   └── 06_NEXT_ACTIONS.md
├── references/          # (ユーザー管理) 論文PDFやメモを格納
│   └── example_paper.pdf
├── src/                 # ツール本体のソースコード
├── tests/               # テストコード
├── run.py               # 実行スクリプト
├── config.yaml          # 動作設定ファイル
├── .env                 # 環境変数
└── .gitignore
```

### 3. 主要コンポーネント仕様

#### 3.1. 入力

*   **FigJamボード**: ユーザーのブレインストーミングの場。
*   `/references/` **ディレクトリ**: ユーザーが収集した文献資料。
*   `config.yaml`: FigJamの記法定義などを含む設定ファイル。

#### 3.2. 出力 (`/context/` ディレクトリ)

*   `01_RESEARCH_LOG.md`: 研究の目的、現状サマリー、FigJamの変更履歴（意味的要約）を時系列で記録。
*   `02_FIGJAM_SNAPSHOT.md`: 現在のFigJamの状態を人間が読める形式で表現したスナップショット。
*   `03_STRUCTURED_DATA.json`: 全オブジェクトの構造化データ。機械処理用。
*   `04_KEY_CONCEPTS.md`: プロジェクト固有の重要概念をまとめた用語集。
*   `05_ISSUES_AND_HYPOTHESES.md`: 現在の「未解決の問い」と「検証すべき仮説」のリスト。
*   `06_NEXT_ACTIONS.md`: `05`を基に生成された、具体的な次の調査項目とプロンプトのドラフト。

#### 3.3. 役割分担

*   **本ツール (`run.py`)**: **知識キュレーター**。FigJamと文献を読み、`/context/`ディレクトリへの**書き込み**を行う唯一のコンポーネント。
*   **外部AI CLI (Gemini等)**: **思考パートナー**。`/context/`と`/references/`を**読み込み**、ユーザーとの対話を行う。ファイルへの書き込みは行わない。
