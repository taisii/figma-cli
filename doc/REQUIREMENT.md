# 研究支援 CLI ツール ドキュメント

## Part 1: 要件定義書 (Requirements Definition Document)

### 1. 概要

本ドキュメントは、研究活動におけるアイデア整理からアウトライン作成までを支援する CLI ツールの要件と設計を定義する。
このツールは、Figma 社のオンラインホワイトボードツール「FigJam」上のブレインストーミング内容を、生成 AI を活用して解釈・構造化し、マークダウン形式の研究アウトラインを半自動で生成・更新することを目的とする。

### 2. 目的と背景

研究プロセスにおいて、発散したアイデアや乱雑なメモを構造化された文章にまとめる作業は、多くの時間と労力を要する。本ツールは、この創造的でありながら煩雑なプロセスを自動化することで、研究者がより本質的な思考や実験に集中できる環境を提供することを目的とする。

### 3. ターゲットユーザー

- 論文やレポートを執筆する研究者、大学院生、学生
- FigJam でアイデア出しや情報整理を行う企画者、ライター、コンサルタント

### 4. 機能要件

| ID   | 要件名                         | 概要                                                                                                                                                                                               |
| :--- | :----------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-1 | **FigJam ボードの読込機能**    | 指定された FigJam ボードの URL から、API 経由でオブジェクト（付箋、テキスト、コネクター等）の情報を取得できる。                                                                                    |
| FR-2 | **コンテンツの構造解釈機能**   | 取得したオブジェクトの**位置情報からクラスタリング（グループ化）**を、**色情報からユーザー定義のタグ（例：「重要」「疑問点」）**を抽出し、接続関係（矢印）と合わせてアイデアの論理構造を解釈する。 |
| FR-3 | **AI によるアウトライン生成**  | 解釈した構造とテキスト情報をコンテキストとして生成 AI に渡し、階層化されたマークダウン形式のアウトラインを生成させる。初回実行と差分更新の両方に対応する。                                         |
| FR-4 | **差分更新機能**               | 前回の実行時と比較して、FigJam ボード上の変更点（オブジェクトのテキスト、位置、色、接続関係の追加・変更・削除）を検出し、その差分情報のみを AI に伝えてアウトラインを効率的に更新する。            |
| FR-5 | **成果物のバージョン管理機能** | ツール実行時に、更新前の公式アウトライン (`outline.md`) を `outline_history/` フォルダに自動でバックアップし、変更履歴を保存する。                                                                 |
| FR-6 | **実行ログの保存機能**         | AI の生出力結果を、実行ごとにタイムスタンプ付きのファイルとして `logs/` フォルダに保存し、デバッグや思考プロセスの追跡を可能にする。                                                               |

### 5. 非機能要件

| ID    | 要件名           | 概要                                                                                                                  |
| :---- | :--------------- | :-------------------------------------------------------------------------------------------------------------------- |
| NFR-1 | **操作性**       | CLI 上でのシンプルなコマンド (`python run.py`) 実行のみで、全ての処理が完結する。                                     |
| NFR-2 | **独立性**       | 動作にあたり、Git のような外部のバージョン管理システムへの依存をなくし、ツール単体で全ての機能が完結する。            |
| NFR-3 | **セキュリティ** | API キーなどの機密情報は、Git 管理外の `.env` ファイルで管理し、外部への漏洩リスクを低減する。                        |
| NFR-4 | **拡張性**       | 将来的に Web UI などを追加開発する際に、本ツールのコアロジックをエンジンとして再利用しやすい、疎結合な設計とする。    |
| NFR-5 | **設定可能性**   | 色の意味定義やグルーピングの閾値など、構造解釈のロジックを外部の設定ファイル (`config.yaml`) でユーザーが変更できる。 |

## Part 2: 基本設計書 (Basic Design Document)

### 1. システムアーキテクチャ

本ツールは、ユーザーのローカルマシン上で実行される単一の Python スクリプトとして実装される。外部とは Figma API および生成 AI サービスの API を介して通信する。

[User] ---runs---> [run.py] <---> [Local Filesystem (cache, logs, etc.)]
`                  |`
`                  +---calls---> [Figma API]`
`                  |`
`                  +---calls---> [Generative AI API]`

### 2. ディレクトリ構成

my_research_project/
├── .env # API キー、FigJam URL などの環境変数を定義
├── .gitignore # Git 管理から除外するファイルを指定
├── config.yaml # 色のマッピングなど、構造解釈ルールを定義
├── run.py # メイン処理を記述した実行スクリプト
├── cache.json # FigJam ボードの前回状態を保存するキャッシュファイル
├── outline.md # 現在の最新版となる公式アウトライン
├── outline_history/ # 過去の公式アウトラインのバージョンが保管されるディレクトリ
│ └── (例: 2025-07-19_10-45.md)
└── logs/ # AI の生出力が毎実行ごとに保存されるディレクトリ
└── (例: 2025-07-19_10-45_raw.md)

### 3. データフローと処理ロジック

ユーザーが `python run.py` を実行した際の処理フローは以下の通り。

1.  **コンテキスト読込**: `.env` から API キーと URL を、`config.yaml`から構造解釈ルールを、`cache.json` から前回のボード状態を、`outline.md` から前回の公式アウトラインを読み込む。
2.  **旧アウトライン退避**: `outline.md` が存在する場合、`outline_history/` にタイムスタンプ付きで移動する。
3.  **Figma データ取得**: Figma API を呼び出し、最新のボード情報を取得する。
4.  **差分検出**: `cache.json` の内容と最新のボード情報を比較し、オブジェクトの`{added, modified, deleted}`をリストアップする。`modified`にはテキスト、位置、色、接続関係の変更を含む。
5.  **プロンプト生成**: `outline.md`の有無で処理を分岐。
    - **存在しない場合(初回実行)**: 最新のボード情報全体と構造解釈の結果（グルーピング情報など）を基に、後述する**初回実行用プロンプト**を生成する。
    - **存在する場合(差分更新)**: 「4.」の差分情報と「1.」で読み込んだ旧アウトラインを基に、後述する**差分更新用プロンプト**を生成する。
6.  **AI 実行**: 生成 AI の API を呼び出し、プロンプトを送信して新しいアウトラインのテキストを受信する。
7.  **成果物保存**:
    a. AI からの生出力を `logs/` にタイムスタンプ付きで保存する。
    b. 同じ内容を `outline.md` としてルートに新規保存する。
8.  **キャッシュ更新**: 「3.」で取得した最新のボード情報を `cache.json` に上書き保存する。

### 4. 主要コンポーネント仕様

#### 4.1. 入力 (Input)

- **`.env` ファイル**:
  - `FIGMA_API_TOKEN`: Figma のパーソナルアクセストークン
  - `FIGJAM_BOARD_URL`: 対象となる FigJam ボードの URL
- **`config.yaml`**: 色のマッピング定義など、構造解釈の挙動を制御する設定。
- **`cache.json`**: FigJam オブジェクトのリスト。各オブジェクトは `{id, text, color, position, ...}` といった情報を持つ。
- **`outline.md`**: 前回の実行で生成されたマークダウン形式のアウトライン（差分更新時に使用）。

#### 4.2. 出力 (Output)

- **`outline.md`**: AI によって生成された最新の公式アウトライン。
- **`outline_history/` 内のファイル**: 過去の `outline.md` のバックアップ。
- **`logs/` 内のファイル**: AI の生出力の記録。
- **`cache.json`**: 更新された最新のボード状態。

### 5. 使用技術スタック (案)

- **言語**: Python 3.9+
- **ライブラリ**:
  - `requests`: API 通信用
  - `python-dotenv`: `.env` ファイル読込用
  - `PyYAML`: `config.yaml` 読込用
  - `google-generativeai`: 各生成 AI サービス用
- **外部サービス**:
  - Figma API
  - Generative AI API (e.g., GPT-4, Gemini)
