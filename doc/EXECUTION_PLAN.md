# Codex CLI 研究支援ツール 実行計画

## 1. プロジェクト概要

本計画は Codex CLI を介して論文 PDF を取り込み、必要に応じて Codex プロンプトでサマリーを生成する軽量ワークフローの整備を目的とする。Nougat による Markdown 化をデフォルトとし、サマリーはユーザーがタイミングを見て実行できるようオンデマンド化する。

## 2. 開発アプローチ

- **小さな単位での反復**: 取り込み・サマリー生成・メタデータ更新を個別に実装・検証する。
- **疎結合設計**: Codex プロンプト呼び出しや Nougat 呼び出しは専用モジュールに切り分け、再利用性を高める。
- **モック駆動テスト**: LLM と外部コマンドはモックで置き換え、副作用なしにテストする。

## 3. 実装フェーズ

### フェーズ 0: 基盤整備
- `config.yaml` に Codex プロンプトや PDF 取り込み関連の設定を追加。
- `.env` から `AI_API_KEY` を読み取り、Codex コマンド実行時に利用する。
- Codex CLI エントリーポイント（`codex_cli.py`）を配置し、`run.py` からフォワード。

### フェーズ 1: PDF 取り込み
- Nougat CLI を呼び出して Markdown (`paper.md`) を生成。
- PDF メタデータ（タイトル、著者、発行年など）を抽出し、スラッグ生成と `metadata.yaml` の作成を行う。
- 一次索引は分離管理。論文は `context/papers/index.yaml`、ノートは `context/notes/index.yaml` を更新。

### フェーズ 2: サマリー生成
- `pdf_ingestor.py` にオンデマンド要約メソッドを実装し、Codex CLI から任意のタイミングで呼び出せるようにする。
- サマリー生成時に `summary.md` とメタデータ (`summary_generated`, `summary_updated_at`) を更新し、API コストが不要な利用ケースではスキップできるようにする。

### フェーズ 3: CLI 体験の向上
- `codex_cli.py` に `ingest pdf` コマンドを実装し、単一ファイルまたはバッチ処理をサポート。
- `codex_cli.py summarize paper` コマンドを追加し、オンデマンドで要約を生成できるようにする。
- `--force`、`--nougat-model` などのオプションを提供。
- 実行結果を標準出力に整形して、Codex セッションで利用するパスがすぐわかるようにする。

## 4. テスト戦略

- **ユニットテスト**: `pdf_ingestor.py` の各ヘルパー（メタデータ抽出、スラッグ生成、インデックス更新など）を対象にモック化したテストを用意する。
- **統合テスト（将来）**: Nougat と Codex コマンドをスタブで置き換えたエンドツーエンドテストを追加し、CLI コマンドからのフローを検証する。
- **フォールバック検証**: LLM の応答が得られない場合でも処理が継続し、warning が `metadata.yaml` に記録されることを確認する。

## 5. 運用ノート

- Nougat CLI は事前インストールが必要。`config.yaml` でモデルを指定したい場合は `pdf_ingest.nougat_model` を利用する。
- `context/` 以下の生成物は再生成可能だが、手作業で編集した場合はバックアップを残しておく。
- 将来的に FigJam や別ソースを追加する場合は、別モジュールとして `src/` に追加し、Codex CLI のサブコマンドを増やす方針とする。
