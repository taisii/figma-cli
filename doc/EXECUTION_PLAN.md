# 研究支援 CLI ツール 実行計画書

## 1. プロジェクト概要

本計画書は、「研究支援 CLI ツール」の開発を、テスト駆動開発（TDD）のアプローチに基づき進めるための実行計画を定義する。要件定義書で定められた各機能を、テストケースを先行して作成しながら段階的に実装していく。

## 2. 開発アプローチ

- **テスト駆動開発 (TDD)**: 各機能について「テスト作成 → 実装 → リファクタリング」のサイクルを回す。これにより、品質の確保と仕様の明確化を図る。
- **モジュール分割**: 機能ごとに Python モジュールを分割し、疎結合で再利用性の高い設計を目指す。
- **イテレーション開発**: 大きな機能を一度に作らず、小さな単位で実装とテストを繰り返す。

## 3. 開発フェーズとタスク

### フェーズ 0: プロジェクト基盤の構築

このフェーズでは、コーディングを開始するための基本的な環境と構造を整備する。

- **タスク:**
    1.  **ディレクトリ作成**: `src`, `tests`, `outline_history`, `logs` などのディレクトリ構造を作成する。
    2.  **ライブラリ選定とインストール**: `requirements.txt` を作成し、`pytest`, `requests`, `python-dotenv`, `PyYAML`, `google-generativeai` などを定義・インストールする。Linterも使用し、Ruffを使用するものとする。
    3.  **設定ファイルテンプレート作成**:
        - `.env.example`: `FIGMA_API_TOKEN`, `FIGJAM_BOARD_URL`, `AI_API_KEY` のテンプレートを記述。
        - `config.yaml`: 色とタグのマッピング定義の例を記述。
    4.  **テスト環境構築**: `pytest` を設定し、簡単なテストが実行できることを確認する。

### フェーズ 1: Figma データ取得機能

FigJam API からボード情報を取得し、アプリケーションで扱える形式に変換するモジュールを開発する。

- **テスト (`tests/test_figma_client.py`):**
    - [ ] ダミーの API レスポンス（JSON ファイル）を読み込み、正しくパースできるかテストする。
    - [ ] API トークンや URL がない場合に、適切なエラーを送出するかテストする。
- **実装 (`src/figma_client.py`):**
    - [ ] `.env` から API トークンと URL を読み込む。
    - [ ] 指定された FigJam ボードの情報を取得するクライアントクラスを実装する。

### フェーズ 2: コンテンツ構造解釈機能

取得した Figma オブジェクトを、位置情報や色情報に基づいて論理的な構造に解釈するモジュールを開発する。

- **テスト (`tests/test_structure_parser.py`):**
    - [ ] **クラスタリング**: 座標が近いオブジェクトが同じグループとして認識されるかテストする。
    - [ ] **タギング**: `config.yaml` の定義に基づき、オブジェクトの色が正しくタグに変換されるかテストする。
    - [ ] **接続関係**: オブジェクト間のコネクター（矢印）情報が正しく抽出されるかテストする。
- **実装 (`src/structure_parser.py`):**
    - [ ] オブジェクトのリストを受け取り、クラスタリング、タギング、接続関係の解析を行うクラス/関数を実装する。

### フェーズ 3: AI プロンプト生成機能

解釈した構造化データを用いて、AI に送信するためのプロンプトを生成するモジュールを開発する。

- **テスト (`tests/test_prompt_generator.py`):**
    - [ ] **初回実行**: 構造化データから、要件定義通りの「初回実行用プロンプト」が生成されるかテストする。
    - [ ] **差分更新**: 差分データと旧アウトラインから、要件定義通りの「差分更新用プロンプト」が生成されるかテストする。
- **実装 (`src/prompt_generator.py`):**
    - [ ] プロンプトテンプレートを管理し、入力データに応じて適切なプロンプトを組み立てるクラス/関数を実装する。

### フェーズ 4: 差分検出とキャッシュ機能

前回の実行状態と比較し、変更点を検出するロジックと、状態を保存/読み込みするキャッシュ機能を開発する。

- **テスト (`tests/test_diff_engine.py`):**
    - [ ] 2つのボード状態（旧・新）を比較し、`added`, `modified`, `deleted` のリストが正しく生成されるかテストする。
    - [ ] テキスト、位置、色、接続関係の変更が `modified` として検出されるかテストする。
- **実装 (`src/diff_engine.py`, `src/cache_manager.py`):**
    - [ ] `cache.json` の読み書きを行う `CacheManager` を実装する。
    - [ ] 2つのオブジェクトリストから差分を検出する `DiffEngine` を実装する。

### フェーズ 5: メインロジックとファイル I/O の統合

すべてのモジュールを統合し、`run.py` を実行した際に一連の処理が正しく行われるようにする。

- **テスト (`tests/test_main_flow.py`):**
    - [ ] **初回実行フロー**: `cache.json` がない状態で実行した際、各モジュールが正しい順序で呼び出され、`outline.md`, `logs/`, `cache.json` が生成されるか、モックを使ってテストする。
    - [ ] **差分更新フロー**: `cache.json` と `outline.md` が存在する状態で実行した際、差分が検出され、アウトラインが更新され、旧アウトラインが `outline_history/` にバックアップされるかテストする。
- **実装 (`run.py`, `src/main_controller.py`):**
    - [ ] `main_controller` に、データフロー全体を制御するロジックを実装する。
    - [ ] `run.py` から `main_controller` を呼び出し、アプリケーションを起動する。

## 4. テスト戦略

- **ユニットテスト**: 各モジュールは独立してテスト可能であるべき。`pytest` を使用し、機能単位でテストケースを作成する。
- **モッキング**: Figma API や Generative AI API などの外部サービスへの依存は、`unittest.mock` や `pytest-mock` を用いてモック化し、テストの安定性と独立性を確保する。
- **カバレッジ**: テストカバレッジを計測し、主要なロジックがテストされていることを確認する。

## 5. 成果物

- **ソースコード**: `src/` ディレクトリ配下の Python モジュール群。
- **テストコード**: `tests/` ディレクトリ配下の `pytest` 用テストスクリプト群。
- **実行スクリプト**: `run.py`
- **設定ファイル**: `config.yaml`, `.env`
- **ドキュメント**: `REQUIREMENT.md`, `EXECUTION_PLAN.md`, `README.md`
